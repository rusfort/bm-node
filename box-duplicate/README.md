# BOX Node: проверка дубликата через CDB → ACB

## Изменение

Меняется только `main/box_reverse.h`: один фиксированный `BOX_TEST_BOX_ID`.

- Было: `10000000-0000-4000-8000-aabbccddeeff`
- Стало: `10000000-0000-4000-8000-aabbccddee01`
- message_id остаётся `20000000-0000-4000-8000-aabbccddeeff`.
- Содержимое сообщения, TTL, тайминги, роли BLE и очередь ACB не меняются.

В текущем проекте TX и RX-фильтр используют одну константу из этого заголовка. Поэтому новое значение одновременно меняет отправляемый контейнер и разрешённый для подтверждения CBB/CDB box_id. Новый box_id фиксирован для этого этапа, НЕ генерируется при каждом подключении. Повторная установка ничего не меняет; для нового прогона после уже успешного теста понадобится ещё один box_id.

Установщик проверяет точки TX/RX и исходный message_id, создаёт отдельный backup-before-duplicate-* и атомарно заменяет только заголовок.

Приложенный `main/box_reverse.h` — готовая версия именно для прочитанного текущего проекта; предпочтительнее применять установщик, чтобы сохранить возможные дополнительные изменения вашего заголовка. Старый apply_reverse.py повторно запускать не надо.

## Предусловие

Сохраните данные Android-приложения и известное тестовое сообщение. Не переустанавливайте приложение, не очищайте его данные и не удаляйте исходное сообщение. Проверяем именно дубликат уже известного message_id, а не повторную доставку нового сообщения.

Если Android не считает этот message_id известным, возможен CBB вместо CDB: такой результат не подтверждает тест дубликата. Не меняйте message_id для «исправления» — это превратит проверку в тест нового сообщения.

## Ожидаемая цепочка

```text
Node: SID → BOX (новый box_id, прежний message_id) → TRM → TRM
Android: распознаёт известный message_id, готовит CDB
Node: принимает CDB для нового box_id
Node: в следующей TX-сессии отправляет ACB с ID этого CDB
Android: удаляет ожидающий CDB, счётчик A увеличивается
```

ACB содержит ID callback, не ID контейнера.

Пример формы логов — НЕ фактический результат аппаратного теста:

```text
Test session started: ... box=10000000-0000-4000-8000-aabbccddee01 message=20000000-0000-4000-8000-aabbccddeeff
BOX_RX: RX CDB id=<callback_uuid> boxes=1 match_test_box=1
BOX_RX: ACB pending: callback_id=<callback_uuid> (RAM, retry 60s)
BOX notify queued: ... type=ACB ...
ACB queued: callback_id=<тот же callback_uuid> (not Android confirmation)
```

Цель: увидеть `RX CDB ... match_test_box=1`, затем ACB для того же ID и увеличение A на Android. При сохранённых предыдущих счётчиках и отсутствии другой активности ориентир: B остаётся 1, A растёт с 1 до 2. Это не жёстко заданная итоговая строка: очереди, другие узлы и дополнительные сеансы влияют на значения.

`D` на Android не обязан расти: здесь Android ОТПРАВЛЯЕТ CDB, а счётчик D относится к ПРИЁМУ CDB. Локальный `ACB queued` сам по себе не доказывает обработки Android.

Если пришёл CBB — пришлите эту строку и новую строку Android-счётчиков. Если пришёл CDB, но A не изменился — пришлите цикл RX CDB → ACB queued целиком. Если callback содержит старый/смешанный box_id, текущий защитный фильтр может его не подтверждать — это не следует обходить массовым ACK чужих ID.

## Откат

Установщик печатает точную команду восстановления. Из `tx`, заменив путь на фактический:

```bash
cp backup-before-duplicate-XXXXXXXX/box_reverse.h main/box_reverse.h
idf.py build
idf.py -p /dev/cu.usbmodem5CCD0111651 flash monitor
```

Откат прошивки не стирает Android-кэш известных BOX. Для повторения проверки с нуля требуется новый box_id при том же message_id.
